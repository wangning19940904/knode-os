    02 · INGEST

    How documents get processed

    A document moves down this list. The stages ask different things of a model, which is why each one can run somewhere else.

    Per stage

    Server-wide: every workspace on this server. Every setting here is one setting for the whole server: the models and connections, embedding, each stage's model and parallel calls, the slots per agent (extraction.workers), the processing limits, research, Ask, languages and retrieval. Saving changes them in every workspace, new ones included. Only what a workspace contains stays its own: its data sources, linked folders and code repositories.

    Convert

    Vision

    Images and scanned PDF pages become searchable Markdown.

    The model has to see pixels: an API provider gets the image inline, codex takes --image, and claude and cursor read the file with their own tools. A text-only model fails here. Changing this re-converts every image and scanned page.

    Index

    Embedding

    Every chunk becomes a vector for semantic and hybrid recall.

    Uses a model pool or a single embedding key. Changing the model or dimensions re-embeds the corpus; rotating keys in a pool does not.

    Manage model pools and per-key budgets in Providers & Agents.

    Extract

    Volume

    Names entities, relations and factual claims in changed documents, a long one in segments; what it finds is checked for duplicates right away.

    The busiest stage — it runs on every changed document, a long one in segments, bounded by the calls per pass here. A fast, cheap model that returns clean JSON is usually the right trade.

    Initializing the wiki first extracts whatever is still queued, for up to this long; the rest is left to the background passes.

    A document longer than 12,000 characters is read in segments, one call each; it may take several passes and is written once every segment is in.

    Summarize

    Prose

    Writes one summary page per document, right after it is extracted.

    One call per document, for people to read rather than a program to parse, so it wants clean prose more than the strongest model. Changing the model does not rewrite summaries already written.

    Runs in Extract's background pass, with its calls per pass and parallel calls.

    Translate

    Languages

    Every document under raw/docs written in another language is translated into the primary one, segment by segment; readers switch between the original and its translation.

    The Markdown is translated, never the original: a PDF or a web page keeps its file, and links, anchors and code stay exactly as they are. Secondary languages are offered to readers and translated when someone asks. Summary pages are written in the primary language. The interface language is each reader's own, not this setting.

    Secondary languages, translated on request:

    Judge

    Quality

    Answers knode_ask and reviews duplicate entities and claims after each extraction pass; overnight it runs Dream and reviews disputed claims.

    Few calls, but each one decides something — whether two entities are one, whether two claims say the same, which of two claims holds, what a week of agent sessions says — so a stronger model pays for itself. Only knode_ask has someone waiting on the answer.

    After each extraction pass the entities and claims it wrote are checked for duplicates, and everything again overnight; a merge can always be undone. Disputed claims are reviewed overnight.

    Processing on this serverServer-wide: every workspace on this server. Extraction, summaries, translations and review calls on this machine's own slots start with the service in every workspace. Remote workers are not counted.
    Server-wide

    Under the floor, nothing that runs on its own spends the plan: extraction, summaries, translations, reviews, research jobs and studies, the nightly Dream and the tier-2 pass all wait until the plan's window resets above it, and Tasks says so. Ask still answers. Codex's windows are read without a model call; Claude's are what its last call here reported. Processing starts with the service in every workspace; Stop processing in Tasks pauses one workspace until the next restart.

    CODE REPOSITORIES

    Code repositories

    Each is kept at one commit in raw/codebase/<name>/ — source, configuration and prose, not dependencies, build output or binaries. Code turns up when a search asks for it (kind code) and agents read and grep it; the repository's card and its documentation in raw/docs/codebase/ are learned from like any document.

    Add a repository

    Globs as in .gitignore, one per line. A repository over 25,000 files or 300 MB is refused — narrow it here.

    Adding a repository fetches it from the network onto the service's machine: an administrator's call.
